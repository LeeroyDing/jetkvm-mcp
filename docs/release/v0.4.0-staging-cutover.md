# v0.4.0 staging cutover

This runbook stages and verifies the six-file `jetkvmctl` release bundle from
the immutable `v0.4.0` tag. It covers the artifact-only
`workflow_dispatch` path and an equivalent isolated local rebuild. It is the
operational record for `oc-2gf`, a child of aftercare epic `oc-6jb`.

## Safety boundary

Staging is deliberately non-production:

- Do not create, move, delete, or push a tag.
- Do not invoke or rerun a tag-push workflow run.
- Do not create, edit, upload to, publish, or delete a GitHub release.
- Do not create, replace, or delete an attestation.
- Do not treat a workflow artifact as an attested release asset.

The workflow has two materially different entry points:

- `workflow_dispatch` runs the reproducible build, checksum validation, and
  artifact-hygiene checks, then uploads one workflow artifact for 14 days.
  Its `attest` and `attach-draft` jobs are skipped.
- A `v*` tag push is the production path. It enforces the tag, `main`, source
  version, and required-check gates, creates attestations, and attaches assets
  to a draft release. Publication is still a separate human action.

The dispatch path decides that it is a dry run from `github.event_name`; it
does **not** enforce the tag gates. Always supply `--ref v0.4.0` and
independently check the resulting `headSha`.

As of 2026-08-21, `v0.4.0` is already published. Its tag-push run was
[31905359949](https://github.com/LeeroyDing/jetkvm-mcp/actions/runs/31905359949).
This aftercare exercise must not replay or alter that production path. In
particular, rerunning the tag job could create another attestation before the
release-attachment job rejects the already-published release.

## Preflight the immutable tag

Fetching is read-only. Run these checks before either staging lane:

```bash
set -euo pipefail

git fetch origin

TAG=v0.4.0
TAG_REF="refs/tags/$TAG"
EXPECTED_TAG_OBJECT=34a9f26e96015f208c5f4d419d94b77fd9c8612d
EXPECTED_COMMIT=8d2b56445e06c88ecbf95f8f4b6ce02131a67ed1

test "$(git cat-file -t "$TAG_REF")" = tag
test "$(git rev-parse "$TAG_REF")" = "$EXPECTED_TAG_OBJECT"
test "$(git rev-parse "$TAG_REF^{commit}")" = "$EXPECTED_COMMIT"
test "$(git ls-remote origin "$TAG_REF" | awk '{print $1}')" = \
  "$EXPECTED_TAG_OBJECT"
test "$(git ls-remote origin "${TAG_REF}^{}" | awk '{print $1}')" = \
  "$EXPECTED_COMMIT"
git merge-base --is-ancestor "$EXPECTED_COMMIT" refs/remotes/origin/main

SOURCE_VERSION="$({
  git show "${EXPECTED_COMMIT}:internal/buildinfo/buildinfo.go"
} | sed -n 's/^[[:space:]]*Version[[:space:]]*=[[:space:]]*"\([^"]*\)".*/\1/p')"
test "$SOURCE_VERSION" = 0.4.0
test "$(git show "${EXPECTED_COMMIT}:.go-version" | tr -d '\r\n')" = 1.26.6
test "$(git show -s --format=%ct "$EXPECTED_COMMIT")" = 1786823533
```

Do not build in the ordinary working tree. Untracked output changes Go's VCS
stamp to `vcs.modified=true`, and `README.md` has changed since this tag even
though it is included in every archive.

## Lane A: GitHub Actions dry run

Use this lane when creating a remote workflow artifact is permitted. It is
the closest rehearsal of the production build without exercising any
production job.

### 1. Dispatch the tag explicitly

The following command creates an Actions run and workflow artifact only. A
recent GitHub CLI returns the URL of the run it created; capture that URL so a
concurrent or older run can never be mistaken for this one:

```bash
set -euo pipefail

EXPECTED_COMMIT=8d2b56445e06c88ecbf95f8f4b6ce02131a67ed1
DISPATCH_OUTPUT="$(
  gh workflow run release.yml --ref v0.4.0 \
    --repo LeeroyDing/jetkvm-mcp
)"
RUN_URL="$(
  awk '
    /^https:\/\/github\.com\/LeeroyDing\/jetkvm-mcp\/actions\/runs\/[0-9]+$/ {
      url = $0
    }
    END { print url }
  ' <<<"$DISPATCH_OUTPUT"
)"
test -n "$RUN_URL"
RUN_ID="${RUN_URL##*/}"
case "$RUN_ID" in
  ''|*[!0-9]*) exit 1 ;;
esac

gh run watch "$RUN_ID" --repo LeeroyDing/jetkvm-mcp --exit-status

RUN_JSON="$(
  gh run view "$RUN_ID" \
    --repo LeeroyDing/jetkvm-mcp \
    --json attempt,event,headBranch,headSha,status,conclusion,url,workflowName
)"
jq -e --arg commit "$EXPECTED_COMMIT" '
  .workflowName == "Release candidate" and
  .event == "workflow_dispatch" and
  .headBranch == "v0.4.0" and
  .headSha == $commit and
  .status == "completed" and
  .conclusion == "success"
' <<<"$RUN_JSON" >/dev/null

ATTEMPT="$(jq -r .attempt <<<"$RUN_JSON")"
ARTIFACT="release-dryrun-0.4.0-${RUN_ID}-${ATTEMPT}"
printf 'run=%s artifact=%s\n' "$RUN_ID" "$ARTIFACT"
```

Never omit `--ref`, and never fall back to selecting the latest matching run
if the created-run URL is absent. Record job results with:

```bash
gh run view "$RUN_ID" \
  --repo LeeroyDing/jetkvm-mcp \
  --json jobs \
  --jq '.jobs[] | [.name,.conclusion] | @tsv'
```

Only `build-checksummed-assets` should do work; the tag-only jobs remain
skipped by their event conditions.

above are the staged bundle.

### 3. Verify `SHA256SUMS`

`SHA256SUMS` contains exactly five filename-sorted entries: `BUILDINFO` and
the four archives. It intentionally does not hash itself.

```bash
set -euo pipefail

test "$(wc -l < "$STAGE_DIR/SHA256SUMS" | tr -d ' ')" = 5
test "$(awk '{print $2}' "$STAGE_DIR/SHA256SUMS")" = \
"$(printf '%s\n' \
  BUILDINFO \
  jetkvmctl_0.4.0_darwin_amd64.tar.gz \
  jetkvmctl_0.4.0_darwin_arm64.tar.gz \
  jetkvmctl_0.4.0_linux_amd64.tar.gz \
  jetkvmctl_0.4.0_linux_arm64.tar.gz | LC_ALL=C sort)"
if command -v sha256sum >/dev/null 2>&1; then
  (cd "$STAGE_DIR" && sha256sum --check SHA256SUMS)
  sha256sum "$STAGE_DIR/SHA256SUMS"
else
  (cd "$STAGE_DIR" && shasum -a 256 -c SHA256SUMS)
  shasum -a 256 "$STAGE_DIR/SHA256SUMS"
fi
```

## Lane B: isolated local reproduction

This is the lane used for the accompanying receipt. The pinned container
matches the workflow's Go version and Linux/amd64 builder platform and supplies
GNU tar. The native macOS `tar` is BSD tar and must not be used to claim
workflow-identical archive bytes.

First repeat the preflight above. Then run the following from any checkout of
this repository. The clone is detached at the peeled tag commit, all output is
outside that clone until the VCS-stamped binaries are complete, and `umask 022`
matches the Actions runner's source-file modes.

```bash
set -euo pipefail
umask 022

REPO_ROOT="$(git rev-parse --show-toplevel)"
COMMIT=8d2b56445e06c88ecbf95f8f4b6ce02131a67ed1
OUT="$REPO_ROOT/dist/v0.4.0-staging"
IMAGE='golang@sha256:116d58cbd88c1297624acc6e967a060012422bacf9930927e23fb719189c6f36'
SCRATCH="$(mktemp -d)"
trap 'rm -rf -- "$SCRATCH"' EXIT
test ! -e "$OUT"

git clone --quiet --no-hardlinks --no-checkout "$REPO_ROOT" "$SCRATCH/source"
git -C "$SCRATCH/source" checkout --quiet --detach "$COMMIT"
test -z "$(git -C "$SCRATCH/source" status --porcelain)"
mkdir -p "$SCRATCH/dist"

docker run --rm --platform linux/amd64 \
  --user "$(id -u):$(id -g)" \
  --env GOCACHE=/work/gocache \
  --env GOPATH=/work/gopath \
  --env GOMODCACHE=/work/gopath/pkg/mod \
  --env GIT_CONFIG_COUNT=1 \
  --env GIT_CONFIG_KEY_0=safe.directory \
  --env GIT_CONFIG_VALUE_0=/work/source \
  --mount "type=bind,source=$SCRATCH,target=/work" \
  --workdir /work/source \
  "$IMAGE" bash -s <<'CONTAINER'
set -euo pipefail
umask 022
export LC_ALL=C GOTOOLCHAIN=local

VERSION=0.4.0
COMMIT=8d2b56445e06c88ecbf95f8f4b6ce02131a67ed1
EPOCH=1786823533
BUILD_DATE=2026-08-15T19:52:13Z
STAGE=/work/stage
REBUILD=/work/rebuild
DIST=/work/dist
STRINGS=/work/strings

test "$(go env GOVERSION)" = go1.26.6
test "$(tr -d '\r\n' < .go-version)" = 1.26.6
test "$(git rev-parse HEAD)" = "$COMMIT"
test -z "$(git status --porcelain)"
mkdir -p "$STAGE" "$REBUILD"
export SOURCE_DATE_EPOCH="$EPOCH"
LDFLAGS="-buildid= -s -w -X github.com/leeroyding/jetkvm-mcp/internal/buildinfo.Version=$VERSION -X github.com/leeroyding/jetkvm-mcp/internal/buildinfo.Commit=$COMMIT -X github.com/leeroyding/jetkvm-mcp/internal/buildinfo.BuildDate=$BUILD_DATE"

for target in darwin/amd64 darwin/arm64 linux/amd64 linux/arm64; do
  goos="${target%/*}"
  goarch="${target#*/}"
  archive="jetkvmctl_${VERSION}_${goos}_${goarch}"
  stage="$STAGE/$archive"
  rebuilt="$REBUILD/$archive/jetkvmctl"
  mkdir -p "$stage" "$(dirname "$rebuilt")"

  CGO_ENABLED=0 GOOS="$goos" GOARCH="$goarch" \
    go build -trimpath -ldflags "$LDFLAGS" \
    -o "$stage/jetkvmctl" ./cmd/jetkvmctl
  CGO_ENABLED=0 GOOS="$goos" GOARCH="$goarch" \
    go build -trimpath -ldflags "$LDFLAGS" \
    -o "$rebuilt" ./cmd/jetkvmctl
  cmp "$stage/jetkvmctl" "$rebuilt"

  go version -m "$stage/jetkvmctl" > "$REBUILD/$archive.go-version-m"
  grep -F $'\tbuild\tvcs=git' "$REBUILD/$archive.go-version-m"
  grep -F $'\tbuild\tvcs.revision='"$COMMIT" \
    "$REBUILD/$archive.go-version-m"
  grep -F $'\tbuild\tvcs.time='"$BUILD_DATE" \
    "$REBUILD/$archive.go-version-m"
  grep -F $'\tbuild\tvcs.modified=false' "$REBUILD/$archive.go-version-m"

  cp LICENSE README.md "$stage/"
  sed '1s|^[^:]*:|jetkvmctl:|' "$REBUILD/$archive.go-version-m" \
    > "$stage/GO-BUILDINFO.txt"
done
test -z "$(git status --porcelain)"

# Extract the exact gitleaks configuration embedded in this tag's workflow.
ARTIFACT_SCAN_CONFIG=/work/gitleaks-release-artifacts.toml
sed -n '179,198p' .github/workflows/release.yml | \
  sed 's/^          //' > "$ARTIFACT_SCAN_CONFIG"
go run github.com/zricethezav/gitleaks/v8@v8.24.3 detect \
  --no-git --source "$STAGE" --config "$ARTIFACT_SCAN_CONFIG" \
  --redact --no-banner

mkdir "$STRINGS"
binary_count=0
while IFS= read -r -d '' binary; do
  binary_count=$((binary_count + 1))
  strings -a "$binary" > "$STRINGS/binary-${binary_count}.txt"
  test -s "$STRINGS/binary-${binary_count}.txt"
done < <(find "$STAGE" -type f -name jetkvmctl -print0 | sort -z)
test "$binary_count" -eq 4
go run github.com/zricethezav/gitleaks/v8@v8.24.3 detect \
  --no-git --source "$STRINGS" --config "$ARTIFACT_SCAN_CONFIG" \
  --redact --no-banner
canary_matches="$(
  find "$STAGE" "$STRINGS" -type f -size -50M \
    -exec grep -a -E -l \
    'CREDENTIAL-CANARY|PASSWORD-CANARY|TOKEN-CANARY|USERINFO-CANARY|QUERY-CREDENTIAL|sup3r-s3cret' \
    {} + || true
)"
test -z "$canary_matches"

for target in darwin/amd64 darwin/arm64 linux/amd64 linux/arm64; do
  goos="${target%/*}"
  goarch="${target#*/}"
  archive="jetkvmctl_${VERSION}_${goos}_${goarch}"
  tar --sort=name --mtime="@$EPOCH" --owner=0 --group=0 --numeric-owner \
    -C "$STAGE" -cf - "$archive" | \
    gzip -n -9 > "$DIST/$archive.tar.gz"
  tar --sort=name --mtime="@$EPOCH" --owner=0 --group=0 --numeric-owner \
    -C "$STAGE" -cf - "$archive" | \
    gzip -n -9 > "$REBUILD/$archive.tar.gz"
  cmp "$DIST/$archive.tar.gz" "$REBUILD/$archive.tar.gz"
done

{
  echo "version=$VERSION"
  echo "commit=$COMMIT"
  echo "buildDate=$BUILD_DATE"
  echo "sourceDateEpoch=$EPOCH"
  echo "goVersion=$(go version)"
  echo 'targets=darwin/amd64,darwin/arm64,linux/amd64,linux/arm64'
  echo 'runtimeDependency=ffmpeg'
} > "$DIST/BUILDINFO"
(
  cd "$DIST"
  sha256sum BUILDINFO jetkvmctl_*.tar.gz | sort -k2 > SHA256SUMS
  sha256sum --check SHA256SUMS
)

VERIFY=/work/verify
mkdir "$VERIFY"
tar -xzf "$DIST/jetkvmctl_${VERSION}_linux_amd64.tar.gz" -C "$VERIFY"
binary="$VERIFY/jetkvmctl_${VERSION}_linux_amd64/jetkvmctl"
version_json="$($binary --version)"
grep -F '"version": "0.4.0"' <<<"$version_json"
grep -F '"commit": "8d2b56445e06c88ecbf95f8f4b6ce02131a67ed1"' \
  <<<"$version_json"
go version -m "$binary" > "$VERIFY/go-version-m"
grep -F $'\tbuild\tvcs.revision='"$COMMIT" "$VERIFY/go-version-m"
grep -F $'\tbuild\tvcs.modified=false' "$VERIFY/go-version-m"

expected="$(printf '%s\n' \
  BUILDINFO \
  SHA256SUMS \
  jetkvmctl_0.4.0_darwin_amd64.tar.gz \
  jetkvmctl_0.4.0_darwin_arm64.tar.gz \
  jetkvmctl_0.4.0_linux_amd64.tar.gz \
  jetkvmctl_0.4.0_linux_arm64.tar.gz | sort)"
actual="$(find "$DIST" -maxdepth 1 -type f -printf '%f\n' | sort)"
test "$actual" = "$expected"
test "$(wc -l < "$DIST/SHA256SUMS")" -eq 5
CONTAINER

mkdir -p "$(dirname "$OUT")" "$OUT"
cp -R "$SCRATCH/dist/." "$OUT/"
if command -v sha256sum >/dev/null 2>&1; then
  (cd "$OUT" && sha256sum --check SHA256SUMS)
  sha256sum "$OUT/SHA256SUMS"
else
  (cd "$OUT" && shasum -a 256 -c SHA256SUMS)
  shasum -a 256 "$OUT/SHA256SUMS"
fi
```

The two `go build` calls and two tar/gzip pipelines per target must all pass
`cmp`. A first local pass under `umask 077` will have identical payload bytes
but different tar header modes for `LICENSE` and `README.md`; it is not the
canonical Actions-compatible bundle. Use `umask 022` as shown.

To compare a local bundle with a downloaded dry-run artifact:

```bash
diff -u "$OUT/SHA256SUMS" "$STAGE_DIR/SHA256SUMS"
for local_file in \
  "$OUT/BUILDINFO" \
  "$OUT/SHA256SUMS" \
  "$OUT"/jetkvmctl_0.4.0_*.tar.gz; do
  file="${local_file##*/}"
  cmp "$local_file" "$STAGE_DIR/$file"
done
```

## Human promotion for a future version

A dry-run artifact is evidence, not a directly promotable release object.
For a future version that has not been tagged or published, an authorized
human would:

1. Confirm the selected commit is on `main`, the aggregate `test` check is
   successful, the source version and changelog are final, and the dry-run
   workflow against the approved commit or branch and/or an isolated local
   reproduction has passed. The existing-tag `v0.4.0` rehearsal in this
   runbook is an aftercare exception, not the normal pre-tag sequence.
2. Create the new immutable semantic-version tag and push it. That tag push
   invokes the production workflow, which rebuilds the assets, applies the
   tag/main/check gates, creates attestations, and creates or updates a draft
   GitHub release.
3. Download the draft assets, repeat the checksum, `BUILDINFO`, `--version`,
   and VCS checks above, verify the attestation, and only then publish the
   draft as a separate human decision.

For clarity, the production transition for an approved **future** version
would have this shape. These commands are reference material and must never be
run with `FUTURE_TAG=v0.4.0`:

```bash
set -euo pipefail

: "${FUTURE_TAG:?export FUTURE_TAG to a new vX.Y.Z tag}"
: "${FUTURE_COMMIT:?export FUTURE_COMMIT to its approved main commit}"
[[ "$FUTURE_TAG" =~ ^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$ ]]
[[ "$FUTURE_COMMIT" =~ ^[0-9a-f]{40}$ ]]
test "$FUTURE_TAG" != v0.4.0

test "$(git rev-parse "${FUTURE_COMMIT}^{commit}")" = "$FUTURE_COMMIT"
git merge-base --is-ancestor "$FUTURE_COMMIT" refs/remotes/origin/main
SOURCE_VERSION="$({
  git show "${FUTURE_COMMIT}:internal/buildinfo/buildinfo.go"
} | sed -n 's/^[[:space:]]*Version[[:space:]]*=[[:space:]]*"\([^"]*\)".*/\1/p')"
test "$FUTURE_TAG" = "v$SOURCE_VERSION"
test -z "$(git ls-remote origin "refs/tags/$FUTURE_TAG")"
if git show-ref --verify --quiet "refs/tags/$FUTURE_TAG"; then
  printf 'refusing to replace existing local tag %s\n' "$FUTURE_TAG" >&2
  exit 1
fi

git tag -a "$FUTURE_TAG" "$FUTURE_COMMIT" \
  -m "jetkvmctl $FUTURE_TAG"
git push origin "refs/tags/$FUTURE_TAG"

# Watch the new tag-push run. The workflow creates an attested draft only.
gh run list \
  --repo LeeroyDing/jetkvm-mcp \
  --workflow release.yml \
  --event push \
  --branch "$FUTURE_TAG" \
  --limit 1
```

After verification, publish that draft through GitHub as the distinct human
approval step; the workflow never publishes it automatically.

Those production actions are intentionally **not commands for this staging
task**. For `v0.4.0` specifically, promotion already happened: never move,
delete, recreate, re-push, or rerun the tag, and do not call `gh release
create`, `gh release upload`, `gh release edit`, or any attestation mutation.
